### Changed

- Planned Core restarts use a fail-closed preparation and database-drain sequence before runtime ownership is quiesced.
- Connection, session-control, migration, idempotency, outbox, Saga, and lease paths use bounded work and durable authority checks.
- A runtime database-health circuit closes player admission on a returned UTC-probe failure, an adapter exception, or a fixed five-second fail-closed watchdog; it keeps bounded diagnostics and connection-heartbeat cleanup operational and suspends the other database-backed scheduled work. A completed failure can recover after two successful probes plus reconciliation. A watchdog cannot cancel an oxmysql `Await`; a lost oxmysql `2.14.1` callback stays fail-closed until MariaDB is restored and the complete FXServer process is restarted once.
- Core documentation keeps the five-item Beta closure line separate from post-Beta soak, evidence-runner, historical-upgrade, extensive restore, and additional non-critical ABI work, and keeps every non-Core rework snapshot outside the beta claim.
- Groups persistence uses Core-owned database contracts, forward-only owned migrations, optimistic concurrency, atomic idempotency receipts, durable effects, and owner-epoch cleanup; no Groups client, NUI, gameplay, payroll, account, inventory, vehicle, world, or interaction authority is introduced.
- Group creation, approval requests, renames, and retries share a durable slug-reservation invariant. Static definitions materialize supported organization structures and fail closed on destructive drift until references are reconciled.
- Groups keeps `synex_core` as its only direct runtime dependency and remains non-critical (`critical: false`). Of its 71 contracts, 70 are server-only and exactly `synex.groups.self.snapshot` is `client-to-server`; the Core session supplies the actor identity and enforces its rate limit.
- DataPort now serializes each idempotency key independently, runs handlers without holding global or owner capacity locks, and acquires those capacity locks only after the handler result is validated. Domain-deletion retention is bounded to 10,000 retained plans globally and 1,000 per requester; every state counts until physical purge, pending/executing plans are never purged automatically, and terminal plans retain their replay key for 30 days before bounded compare-and-swap compaction releases capacity and permits key reuse.
- Groups registration is resumable and generation-fenced. Its service remains `UNHEALTHY` behind a readiness barrier until the deletion provider, character participant, service, 71 RPCs, and five workers are registered; retryable failures resume the same journal after five seconds, while non-retryable failures remain terminal and fail closed.
- Extension providers now begin each resource epoch with `synex.groups.registries.begin`. The persisted generation and exact owner epoch fence complete-set registration, hydration, and stop cleanup so stale callbacks cannot reactivate or remove a newer restart's definitions.
- Groups reads use contract-specific page limits plus a final 30,000-byte response guard; relationship and assignment detail metadata is capped at 16 KiB, and the client self snapshot is capped at eight memberships and eight roles per membership.
- Grade, role-source, policy-rule, and default-capability definitions use a bounded revision-keyed cache with defensive copies, mutation/mismatch invalidation, restart-empty state, and Doctor-visible hit/miss/write/invalidation/eviction metrics.
- Accounts financial mutations use deterministic account locking, optimistic sequence/version checks, bounded deadlock/lock-timeout retry, principal-scoped idempotency, reject-only pre-transaction/transfer/hold-capture hooks, and transactionally co-located ledger, snapshot, audit, and outbox writes.
- The Accounts control and CLI surfaces now expose bounded status, Doctor, transaction/account investigation, dead-outbox inspection, integrity findings, and economy aggregates. `synex accounts reconcile` remains an explicit console/ACE-restricted, capability-declared, audited mutation and performs no automatic repair.
- The reviewed legacy importer now maps one through 32 configured currencies, including explicit ESX `money`, `bank`, and `black_money` mappings, into principal-scoped multi-leg opening transactions with signed entries and ready mint/burn topology instead of assigning balances directly.
- Legacy job and gang imports now consume the same catalog-bound provider/group/grade definitions as the runtime Bridge, resolve only existing active Groups targets, and fail closed on unknown, inactive or ambiguous mappings instead of creating synthetic organizations or grades.
- Entity mutations use caller/resource-epoch fences, per-Entity or binding lanes, optimistic versions and live authority leases; spawn admission applies total/resource/logical-owner/bucket/persistent/type quotas and bounded resource/type/bucket rate windows. Routing-bucket changes are owner/generation-fenced, and observed out-of-band Entity/player moves are audited and reverted.
- World keeps static definitions resource-owned and atomically swaps only fully validated dependency closures. Dynamic state is schema/version fenced; server-observed position, session generation, map availability, definition revision and instance/bucket generation are revalidated around yielding access, transition and membership operations. Spatial queries, client slices, Control payloads, workers and cleanup queues are explicitly bounded.
- Control now keeps raw provider cursors server-side behind 120-second player/scope-bound handles, caches only overview and cursor/limit-specific provider-catalog pages, and invalidates cache/cursors plus open-view navigation when a Synex resource starts or stops.
- Diagnostic bundles now sanitize the complete artifact under the Control protection contract and accept repository-contained operator evidence through `doctor --bundle --runtime-evidence <file>`; absent evidence is explicitly recorded as `RUNTIME_CONTROL_EVIDENCE_NOT_SUPPLIED` rather than inferred.
- Bridge provider parity now includes QB/ESX stable-identifier lookup and bounded active-player enumeration, a read-only QBX offline projection, identifier-capable QBX money/metadata/group/duty operations and standalone primary-group exports, catalog-driven ESX accounts, and read-only QB/ESX permission projection. Offline mutation and permission administration remain unsupported.
- Compatibility global lifecycle payloads are data-only; privileged Player/xPlayer methods stay behind caller-bound server exports. Client player-data and callback exports use separately resolved bounded consumer allowlists as API admission, without treating client resource identity as confidentiality or server authority.
- QB Core Object filtering and every cataloged job, gang/group, duty, money, or account update-event family now require their own surface authorization instead of inheriting base object or lifecycle access.
- Accounts and Groups invalidation targets only matching character projections when the event contains one safe identity, with bounded global fallback for missing, malformed, or conflicting identity fields. Mapped metadata writes queue one exact source/character/session-generation refresh.
- Shared QBCore lifecycle ownership is evaluated from live provider/consumer state and authorization: QB has priority, QBX is the fallback, and a running handoff does not replay a synthetic unload/load. Provider recovery rehydrates active projections without replaying public load, and eligible consumers can take publication authority after another consumer stops. Historical-name facades remain privileged trusted-computing-base code.

### Security

- Core capability checks remain caller-bound and fail closed; Core client and cross-resource transport inputs are bounded and validated at their server boundary. Non-Core NUI/resources remain outside the supported beta scope.
- Security treats client Sentinel observations as weak evidence, keeps domain prevention and authority in Core/Accounts/Entities/World/Interact, bounds and redacts persisted summaries and diagnostics, and requires capability-, owner-, session-, generation-, expectation-, evidence- and rate-limit checks at its integration boundaries. Its default profile is observe-first; automatic kick and ban remain disabled pending live acceptance and false-positive calibration.
- Runtime and repository security checks redact sensitive values and reject secret-bearing or unsafe live-test bundles.
- Entity contracts remain server-only and capability-gated. Network ownership is exposed only as transport state, `synex_control` receives read/query capabilities only, and Entity diagnostics observe rather than mutate global OneSync/state-bag policy.
- World mutation contracts remain server-only and capability-gated. Client World events are closed server-to-client projections only; cached Context is marked observed and is never authorization truth. Bundle ownership, caller/resource epochs, per-caller idempotency, map and WorldRef revisions, server proximity and Entity bucket generations fail closed at their authority boundaries.
- The shared UI runtime accepts only fixed callback routes and bounded typed payloads; generic surfaces do not accept arbitrary HTML, SVG, URLs, event names, server events or gameplay-authoritative state. Consumer resources remain responsible for their own server authorization and domain validation.
- Notify accepts no client-selected player target, system origin, banner or privileged priority. Server delivery revalidates the exact active session and source generation; priority and broadcast operations require explicit grants; action tokens are bounded, expiring, single-use and session-fenced; normal notifications never request NUI focus.
- Notify server delivery now emits only opaque wake identifiers. The active target redeems each short-lived command exactly once through a session/source-generation-fenced Core RPC; pending transport state is globally and per-source bounded, expires automatically, and is exposed as real pressure rather than fabricated display metrics.

No production-stable version has been released yet. An entry will move out of **Unreleased** only after the exact release revision passes the canonical gate and the project owner explicitly publishes it.
